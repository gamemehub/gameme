## 1. ベンチマーク：MOTHER系ゲームは実際どう作られ、どこで品質を出したか

### Tier S：商業名作（目指す「体験」の基準。製法は真似できない）

| 作品 | 体制・期間 | エンジン | 素材の作り方 | クオリティの源泉 |
|---|---|---|---|---|
| MOTHER2 (1994) | 任天堂/APE/HAL 大規模チーム・約5年（開発難航で有名） | SNES専用 | 専属ドッター多数。斜投影タイル・斜め道路・大型手描き建物 | 糸井重里のテキスト、「現代の日常」という世界観、音楽 |
| Undertale (2015) | ほぼ1人（Toby Fox）・32ヶ月 | GameMaker: Studio | 絵は意図的に素朴（一部Temmie Chang） | **全戦闘が手作りの個性**（敵ごとの弾幕＋会話）、音楽、テキストの間 |
| OMORI (2020) | OMOCAT小チーム・6年以上 | RPG Maker MV | 全て手描き。**ワールドごとに厳格なパレット統一** | アートの統一感、物語、日常と異世界の落差 |

### Tier A：ソロ・少人数の商業成功（目指す「完成度」の基準）

### Tier C：AI駆動の直近事例（今回と同じ製法の先行者）

| 作品 | 体制・期間 | 製法 | 到達点 |
|---|---|---|---|
| モンスター78体ブラウザRPG (2025, 学生) | 1人＋Claude Code | データスキーマ先行→AIで量産 | itch.io公開完走 |
| Catvivors (Steam EA) | 1人＋Claude Code | コードはAI、**24レベルは全て手置き** | Steam Early Access到達 |
| Void Balls (10日間) | 1人＋8並列エージェント | 役割分担（実装/バランス/テスト別エージェント） | 10日で完成・公開 |

### ベンチマークから読み取れる品質法則（重要）

1. **エンジンの高級さと品質は無相関**。RPG Maker 2003製のOFFがカルト的名作である事実が証明。
   Vanilla DOMであること自体は品質の言い訳にも障害にもならない
2. 全Tierに共通する品質源泉は4つだけ：
   **①トーン（世界規約）の徹底統一 ②テキストと「間」 ③音楽・音 ④手作りの個性（エンカウント/違和感イベント）**
3. 素材の量・解像度はTier内でもバラバラ。**「上手い絵」ではなく「揃った絵」が品質**
   （Space Funeralは下手な絵で成立、OMORIはパレット規約で成立）
4. ソロ成功作は例外なく**制作期間の大半をコンテンツの手磨きに使い、システムは既製品**
   （RPG Maker / GameMaker / Unity）。今回AIが代替するのは「既製エンジン＋外注」の部分であり、
   手磨き（ディレクション・テキスト・配置）は代替できない（Catvivorsの24レベル手置きが示す通り）

## 2. 今回の製法（RewriteMemory Production Method v1）

### 2-1. ベンチマーク上の位置づけ（何をどの水準で作るか）

```
素材量     ：OFF級（最小）        … シーン一枚絵＋キャラ数体＋顔アイコン。量で勝負しない
絵の統一   ：OMORI式（規約で統一）… DESIGN_TOKEN＋単一生成モデル＋パレット固定
テキスト   ：Undertale級を目標    … 「間」をデータで制御（[pause]/[speed]マークアップ）
トーン     ：Dreamed Away式       … 「学園・17:17・白層化」の世界規約が全生成物の採用フィルタ
個性       ：Undertale原則        … 違和感イベント・エンカウントは1件ずつ手作り。汎用品を置かない
規模       ：Tier C（AI駆動）     … CH01垂直スライス→スキーマ量産。年単位の開発はしない
```

### 2-2. 体制（三役分業）

| 役割 | 担当 | やること | やらないこと |
|---|---|---|---|
| ディレクター/ライター | 人間 | 面白さの判定、シナリオ正本、違和感イベントの発案、セットピース配置、実機プレイテスト | コードを直接書く |
| 実装 | Claude Code | エンジン実装、スキーマへのデータ流し込み、ヘッドレステスト、リファクタ | コアループの発案、物語判断（MODE_DEFINITION遵守事項どおり） |
| アセット | 画像AI（PixelLab系）＋人間仕上げ | スタイル固定生成→Pixel Snapper量子化→Aseprite仕上げ | 生出力の直接投入 |

### 2-3. 作り方（工程）

1. **エンジン**：現行Vanilla DOM単一HTMLを維持してコアループを完成させる。
   検証後にM02（探索）のみPhaser化、VN/会話UIはDOMのまま重ねる（DEVELOPMENT_GUIDELINES §6）
2. **制作単位は「シーン」**：シナリオ（SCENES）をJSONに分離し、1シーン＝1データ単位で作る。
   AIへの量産指示はJSONのみ（コード全体を触らせない）
3. **順序は垂直スライス先行**：CH01の「探索→違和感→会話→記憶書き換え→世界変化」1周5分を
   仮素材で完成→面白さを実機で判定→OKなら素材差し替えとシーン量産に進む
4. **マップは作らない**：タイルを敷かず、シーンごとの一枚絵背景＋パララックス2-3層（Plan A）。
   違和感オブジェクトだけ個別スプライトで置く
5. **音**：ZzFXでSE、BGMはZzFXMまたはCC0チップチューン。全操作に音を付ける
6. **検証**：(a) Claudeによるヘッドレス全シーン通しテスト（自動）、
   (b) 人間のスマホ実機通しプレイ（毎PR）、(c) 初見者テスト（マイルストーン毎）

### 2-4. クオリティライン（この数値を下回るものは出さない）

- 入力→画面反応 **100ms以内**（`pointerdown`使用、`click`禁止）
- テキストはタップで即全文表示→再タップで次へ（待たせるUI禁止）
- セリフは**1ボックス1情報**、オチは独立ビート
- M04（VN）1回は5分以内、通常は大幅に短く。テキストビート間に操作ビートを挟む
- 全シーンの色はDESIGN_TOKEN由来（マジックナンバー禁止・既存規約どおり）
- アセットは同一モデル・同一パレット・ASSET_SPEC命名。1枚でも例外を入れない
- 違和感イベント・エンカウントは「ジョーク/選択/世界の情報」のどれかを必ず1つ含む。含まないものはカット
- リリース判定：初見の人がスマホで5分遊び、操作に詰まらず「記憶を書き換えたら世界が変わった」と説明できる

### 2-5. やらないことリスト（スコープ防壁・CLAUDE.mdに転記する）

- オープンワールド／見下ろし型タイルマップ（Plan B発動まで）
- ランダムエンカウント、汎用ステータス戦闘（M05はM06とセットになるまで作らない）
- 3D・リアル調・高解像度イラスト（世界規約外）
- 新モードの発明（MODE_DEFINITION M00〜M13の組み合わせのみ）
- 面白さ未検証段階でのエンジン移行・大規模リファクタ
