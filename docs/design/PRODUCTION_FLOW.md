# RewriteMemory 制作フロー（領域別の具体的な作り方）

> 位置づけ：**実行手順書**。DEVELOPMENT_GUIDELINES（課題分析）と BENCHMARK_AND_PRODUCTION（製法定義）を
> 「どの順番で・何を・どう作るか」の具体フローに落としたもの。

- バージョン: v1.0
- 作成日: 2026-07-21

---

## 0. 全体フロー（5フェーズ）

```
Phase 0  準備（1日）          CLAUDE.md / デバッグワープ / シナリオJSON分離
Phase 1  ゲーム性（1-2週）     記憶書き換えループの垂直スライス（仮素材のまま）
Phase 2  見た目（1-2週）       キャラ→UI/UX→マップの順に本素材化
Phase 3  量産（継続）          シーン・NPC・違和感イベントをスキーマ流し込み
Phase 4  調整（各Phase末尾）   実機テスト→具体的観察→修正
```

**原則：Phase 1 が終わるまで Phase 2 に入らない。** 見た目を先に磨くと
「綺麗だが面白くない」で手戻りする（失敗事例の共通パターン）。

---

## Phase 0：準備（すべての土台・1日で終わらせる）

1. **CLAUDE.md 作成**（リポジトリ直下・300行以内）
   - ゲームの本質1行（「記憶を書き換えると世界が変わる探索ADV」）
   - **「何でないか」リスト**（タイルマップRPGではない／オープンワールドではない／
     汎用ステータス戦闘はない）
   - 技術規約：入力は `pointerdown`・反応100ms以内・色はDESIGN_TOKEN経由・
     モードはM00〜M13のみ・完了条件は「実機で遊んで期待通り」
2. **デバッグワープ**：URLパラメータ `?scene=<id>` で任意シーンから開始できるようにする
3. **シナリオのJSON分離**：`index.html` 内の SCENES 配列を `scenes.json` に外出しし、
   fetch で読み込む。以後、AIへのシナリオ追加指示はJSONのみを対象にする
4. **Gap.md 作成**：MODE_DEFINITION / SCREEN仕様と現実装の乖離一覧（PR毎に更新）

## Phase 1：ゲーム性（コアループの垂直スライス）

**ゴール：仮素材のまま「1周5分」が通しで遊べて、面白いかを判定できる状態。**

1. ループの1周を固定する：
   `探索(M02) → 違和感を発見 → 会話(M03/M04) → 記憶書き換え(選択) → 世界の変化を目視 → 探索`
2. **「世界の変化」を最低1つ実装**する（このゲーム固有の報酬）。例：
   - 書き換え前：教室に「消えた椅子の跡」がeerie点滅している
   - 書き換え後：同じ場所に椅子が実在し、座っているNPCが現れ、会話内容が変わる
   - HUDの時刻・背景色・BGMのいずれかも同時に変化させ「世界が動いた」感を出す
3. 選択に**コストと不可逆性**を付ける（書き換えは章内で回数制限／書き換えた記憶の
   元テキストはバックログで「白層化」して読めなくなる等）。コストのない選択は意思決定にならない
4. 実機（スマホ）で通しプレイ→判定。基準：
   - 初見の人が詰まらず5分で1周できる
   - 「記憶を書き換えたら世界が変わった」を自分の言葉で説明できる
   - もう1回書き換えたいと思うか
5. 面白くなければ**ここで直す**（変化の見せ方・選択の重さ・導線）。素材に進まない

## Phase 2A：キャラの作り方

```
1. キャラシート正本（Character Bible）から表情・ポーズ一覧を確定
2. PixelLab（pixellab.ai）で生成
   - 歩行スプライト：まず左右2方向のみ（現探索は横移動）。待機（idle）とまばたき差分
   - 顔アイコン：ASSET_SPEC の7表情（normal/smile/sad/anxious/serious/surprise/empty）
     最小3枚（normal/anxious/empty）から開始
   - プロンプト例：
     "16-bit pixel art character sprite, Japanese high school boy, side view walk cycle,
      2 frames, muted evening palette, EarthBound-inspired, transparent background"
3. Pixel Snapper で真のピクセルグリッドに量子化 → パレット削減
4. Aseprite で仕上げ（パレット統一・フレーム整列・サイズは表示の2倍）
5. ASSET_SPEC 命名で配置（例 mio_face_anxious.png）→ PROMPTS.md に生成条件を記録
6. 組み込み：会話中も止めない（まばたき・微揺れ）。近接発光・eerie演出は現行実装を流用
```

**規約：全キャラを同一ツール・同一パレット・同一プロンプト基調で生成。1枚でも例外を入れない。**

## Phase 2B：UI/UXの作り方

既存の MODE_DEFINITION v1.2 と DESIGN_TOKEN が正本。作り方は「新規発明せず、磨く」：

1. **テキストマークアップ実装**（最優先・効果最大）
   - `[pause:500]` `[speed:0.5]` `[shake]` をtypewrite関数に追加
   - 基準：20-40文字/秒、読点+100ms、句点+300ms、三点リーダー+500ms
   - 1-2文字ごとにキャラ固有ブリップ音
2. **タップ即送りの保証**：1タップ目=全文表示、2タップ目=次へ。全ビート・全モード共通
3. **入力の即応**：`click` を全廃し `pointerdown` に統一。タッチ領域44px以上
4. **状態変化のトゥイーン**：ウィンドウ開閉・選択肢出現・カード選択に150-250msのease
5. **ジュース**：記憶書き換え確定＝白フラッシュ＋微シェイク（trauma²減衰200-300ms）。
   決定音・キャンセル音・ページ送り音をZzFXで全操作に
6. モード遷移は StateMachine 規約どおり（isTransitioning ガード・UI混在禁止）

## Phase 2C：マップ（探索シーン）の作り方

**タイルは敷かない。シーン＝一枚絵ステージ（Plan A）。**

```
1. ラフ構図：紙またはテキストで「左端＝昇降口／中央＝時計塔／右端＝校門」等を決める
   （手描きラフを撮影してAIに渡し、hotspot座標のJSON化までさせてよい）
2. 背景を3層生成（画像AI）：
   - 奥景：空と校舎シルエット（ほぼ動かない）
   - 中景：木・渡り廊下・掲示板（0.5倍速で流れる）
   - 近景：地面・草・小物の影（1倍速）
   - プロンプト例：
     "wide pixel art background, Japanese school courtyard at dusk 17:17, long shadows,
      muted blue-purple palette with warm orange accents, EarthBound-inspired, no characters,
      horizontal panorama 3:1"
3. 量子化・トーン統一（キャラと同一パレットに寄せる）→ 層別PNG
4. 実装：walk-world に3層を重ね、スクロール時 translateX × 深度係数で視差
5. 違和感オブジェクト・NPCは背景に焼き込まず、個別スプライトでJSON配置
   （書き換えで出現/消滅させるため）
6. 仕上げ：画面全体にビネット＋色調オーバーレイのdiv1枚（最安の雰囲気向上）
```

シーン追加は 2→5 の繰り返し。1シーン＝背景3枚＋配置JSON1枚で完結する。

## Phase 2D：音の作り方

1. SE：ZzFX で8種を最初に揃える（決定／キャンセル／ページ送り／ブリップ2種／
   発見（違和感）／書き換え確定／世界変化）。Webツールで音作り→コード1行で再生
2. BGM：ZzFXM（コードのみ）または OpenGameArt CC0 チップチューンから世界観に合う静かな曲。
   探索と書き換え後で微妙に違うバージョンを用意すると「世界が変わった」が音でも伝わる

---

## Phase 3：量産（シナリオ・シーンのスケール）

1. スキーマを固定：シーン／NPC／違和感イベント／会話ビートのJSON型を確定
2. **シナリオ正本（人間）→ JSON流し込み（AI）**の一方通行。AIにコード本体を触らせない
3. 違和感イベントは1件ずつ手作り（Undertale原則：ジョーク／選択／世界の情報の
   いずれか必ず1つ。無いものはカット）
4. ヘッドレステスト：Node で scenes.json の全遷移（next切れ・未定義参照・詰み）を自動検証。
   Claude に全シーン通し読みをさせ、破綻・誤字・トーン逸脱を報告させる

---

## Phase 4：調整（各フェーズ末尾で回す）

1. スマホ実機で通しプレイ（毎PR）
2. 初見者テスト（マイルストーン毎）：口出し禁止で観察。詰まった場所・スキップした場所を記録
3. フィードバックは具体的観察で（「もっと良く」禁止。「◯◯の反応が遅い」「この会話は長い」）
4. 機能追加バーストの後にリファクタリング回を必ず挟む
