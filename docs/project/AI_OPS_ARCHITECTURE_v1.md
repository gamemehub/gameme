## 2. 役割分担（責務分離）

| 主体 | 役割 | **その主体にしかできない/最も向く仕事** | やらないこと |
|---|---|---|---|
| **人間(Chairman/Miya)** | 最終決裁 | **体験の"気持ちよさ"最終判定**、資金・契約、Steam公開/GC応募のGo、価値・倫理・法的判断、方針の最終決定 | 細かいGitHub管理・実装 |
| **GPT** | PM/アーキテクト/設計レビュー/QA/優先順位/リスク管理 | **戦略と判断**：ロードマップ・仕様確定・レビュー基準・優先順位・アーキ整合・リスク評価・Miya向け"おすすめ"提示 | 実装（コードを書かない） |
| **Claude (Claude Code)** | 実装統括＋CI/検証＋Knowledge Manager＋PM補佐 | **リポジトリ直アクセス〜GitHub運用〜CI連携〜実機確認〜docs資産化を一気通貫**。24h自律ループのオーケストレーション。長コンテキスト・ツール実行 | 仕様の最終決定（GPT/人間の領分）、体験の最終判定 |
| **Codex** | 副実装エンジン | **明確な仕様の局所コードを量産/並列**（定型実装・テスト生成）。Claudeが振ったサブタスクの実装、代替系 | 設計判断（迷ったら停止しGPTレビュー待ち） |

**切り分けの原則**
- **判断はGPT/人間、実装はClaude/Codex、承認は人間。**
- Claude と Codex はどちらも実装できるが、**Claude=オーケストレータ兼メイン**（repo/CI/検証/docsまで通す）、**Codex=局所・並列のサブ**。まずClaude単独で回し、量が増えたらCodexを足す（拡張性を保持）。
- 迷い・仕様矛盾・大規模改修・本番影響 → **停止して報告**（PROJECT_OPERATING_SYSTEM §14）。

## 3. 採用構成（C案・確定）
- **対話/軽作業＝Max 20x（$200/月・定額）**：人間＋Claude Codeの対話開発、docs整備。

## 4. コスト試算（前提を明示）

### 4.1 標準運用シナリオ（前提・可変）
| 前提 | 値 |
|---|---|
| 常駐 | 24h（launchd）。ただし"生成中"ではなくイベント/スケジュール駆動 |
| 実タスク | 1日 8〜15件（Ready Issue→実装→PR） |
| 1タスクのmodelターン | 約10〜20 |
| **1日の合計model-turn** | **≈150** |
| 1ターンのトークン | 入力60k（キャッシュ率75%→fresh 15k/cache 45k）＋出力6k |
| モデル比率 | **Sonnet 70% / Opus 15% / Haiku 15%** |
| Batch適用 | 非対話処理の約30%（レビュー/検証） |

### 4.2 1ターン単価（上記トークン・導入価格）
| モデル | fresh入力 | cache読取 | 出力 | 合計/ターン |
|---|---|---|---|---|
| Sonnet 5 | 15k×$2 | 45k×$0.2 | 6k×$10 | **≈$0.099** |
| Opus 4.8 | 15k×$5 | 45k×$0.5 | 6k×$25 | **≈$0.248** |
| Haiku 4.5 | 15k×$1 | 45k×$0.1 | 6k×$5 | **≈$0.050** |

- 加重平均（0.7/0.15/0.15）≈ **$0.114/ターン** → 150ターン/日 ≈ **$17/日**、Batch分で ≈ **$15.5/日**。
- **API月額 ≈ $465（約7.0万円）**。
- 合算：Max $200 ＋ API $465 ＋ GPT/Codexレビュー ~$50 ＋ 電気 ~¥500 ＋ バックアップ按分 ≈ **月 $715〜900 ＝ 約10.7〜13万円**（C案レンジと整合）。

### 4.3 感度（何が効くか）
- **Opus比率**：15%→40%で API月額が約1.6倍。難所限定を厳守。
- **ターン数/日**：150→300で API約2倍。日次上限で制御。
- **キャッシュ率**：75%→50%で入力コスト増。安定プレフィックス設計で維持。
- **Sonnet標準価格移行(9/1)**：$2/$10→$3/$15でSonnet分1.5倍。
→ **必ず自環境で `count_tokens` 実測して4.1の係数を再校正**（要再確認）。

## 5. 運用フロー
```
GPT: Ready Issue作成(仕様/invariant/完了条件) → ラベル ai-ready
        ▼ (Mac mini launchd, 300s間隔)
Dispatcher: ai-ready を1件取得 → claude/ ブランチ作成 → in-progress
        ▼
Claude(主) / Codex(副): 実装 → commit → push
        ▼
auto-pr: PR作成   godot-check(CI): パース/インポート検証(green)
        ▼
自動/GPTレビュー → 人間レビュー待ち(確認レーン) / dev-docsは安全レーンで自動マージ
        ▼
Miya: URLで承認(番号回答) → マージ → Issue close
        ▼
Supervisor: 常時監視(下記) / 日次レポート
```

## 6. Supervisor構成（監視エージェント）
`tools/autonomy/supervisor.sh`（launchd・拡張予定）。**監視項目**：
- APIコスト（日次）／Maxプラン利用状況／エージェント停止（ハートビート24h）
- CI成功率／PR成功率／Issue処理速度／タスク滞留時間
- 無限ループ検知／同一エラー連続検知／自動PR過多（暴走）
- Mac miniリソース（CPU/メモリ/ストレージ）／ネットワーク異常
- **異常時**：通知（ログ→将来Slack/Discord）＋ `PAUSE` 自動設定 ＋ launchd再起動。

## 7. KPI（費用対効果で評価）
「安い」ではなく「費用対効果」。毎日 **AI Studio Daily Report** に自動出力：

| 分類 | 指標 | 目標(初期) |
|---|---|---|
| 稼働 | AI稼働時間 / 停止回数 / 自動復旧回数 | 停止<1回/日 |
| スループット | 完了Issue/日・PR数・レビュー待ち件数 | 完了 8〜15/日 |
| 品質 | **godot-check CI成功率** / マージ後revert率(バグ率) | CI≥90% / revert≤5% |
| 自動化 | 自動マージ率（安全レーン） | ≥80% |
| 速度 | レビュー待ち時間（PR→承認） | 中央値<24h |
| コスト | 日次/月次コスト・**コスト/完了Issue**・**コスト/マージPR** | 監視・上限内 |
| 進捗 | CH01進捗率 / 計画との差異 | 週次で±10%内 |

**費用対効果の主指標＝コスト/マージPR、コスト/完了Issue**。これが下がる構成が最適（＝Sonnet主力＋キャッシュが効く）。
