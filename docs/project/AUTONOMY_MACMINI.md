# Mac mini 24時間自律開発体制 設計書

状態: v0.1 / 設計（GPTレビュー用）
作成: 2026-07-02
目的: Mac mini を常時起動の実行基盤とし、RewriteMemory の開発を「イベント/スケジュール駆動で自動実行し、危険なレーンだけ人間承認」で回す体制を定義する。`PROJECT_OPERATING_SYSTEM`（Issue #47）の *「完全な24時間自律実行は外部実行基盤に依存する」* を、Mac miniで具体化する。

---

## 0. 「24時間自律」の定義（誤解を避ける）
- 目指すのは **「イベント/スケジュール駆動で、区切られたタスクをエージェントが自動実行し、危険レーンのみ人間承認」**。
- 目指さないのは「無人で会社が永遠に考え続ける」こと。これはコスト・安全・品質のいずれでも破綻する。
- 安全レーン（`docs/`・`docs/rewrite-dev/`）は**本当に無人で回せる**。体験に関わる実装（Ch1本体・UI/演出）は**確認レーン**で、どこかで Miya のURL承認が入る（設計通り＝安全）。

---

## 1. Mac mini が担う3つの役割
1. **セルフホスト GitHub Actions ランナー**
   - Godot採用（決定2）に直結。**Windows/mac の exe ビルド・Godotエクスポート・ヘッドレス動作テスト**を常時起動マシンで24h回す。GitHub無料枠・macOS課金に縛られない。
2. **常時起動のエージェント・ホスト**
   - `launchd` 常駐で **Claude Code / Codex CLI をヘッドレス起動**。「Ready課題 → 実装 → push → PR作成」を無人実行。
3. **マルチエージェントのオーケストレータ**
   - 「調査／実装／レビュー」を別エージェントで並列化（GitHub Issue/PRイベント → 担当エージェントに振り分け）。

---

## 2. アーキテクチャ（アウトバウンド中心・イベント＋ループ）
```
GitHub (Issue / PR / CI webhook)
        │  ※アウトバウンド中心（ポーリング or トンネル）。ネットワーク変更に強い
        ▼
Mac mini（常時起動・launchd）
 ├─ ディスパッチャ：Ready課題 / レビュー指摘 / CI失敗 を検知して振り分け
 ├─ 実装エージェント（Codex / Claude Code, headless）→ 実装 → push → PR
 ├─ 検証エージェント（Claude）→ scene整合 / 実機 / 回帰の確認
 └─ セルフホスト Runner → Godot ビルド / exe 出力 / テスト
        │
        ▼
既存の自動レーン（auto-pr → ci(scene-integrity) → auto-merge）※dev/docsのみ無人マージ
        │
        ▼
危険レーン（本番 docs/rewrite/ ・.github/ ・ゲーム核心）＝ Miya が URL で承認
```
- **設計原則：インバウンドを前提にしない**。エージェントもランナーも「Mac mini → 外部API」の外向き接続で完結させる。これによりWi-Fi/ルーター/IPが変わっても動作が途切れない。

---

## 3. 実行前に必要な「前提」
1. **リポジトリ設定（Miya/管理者操作）**
   - Settings → General → **"Allow auto-merge" を ON**
   - **`secrets.GH_PAT`** を設定（PR作成/ラベル付与が下流ワークフローを起動できるように）
   - main のブランチ保護で必須チェック `scene-integrity` を有効化
2. **Mac mini 常駐化**
   - スリープ無効（`caffeinate` or システム設定）、電源復帰後の自動起動、**可能なら有線LAN**
   - 新Wi-Fiを**自動接続**登録、または DHCP予約/固定IP
   - `launchd` で各常駐プロセスを keepalive
   - APIキー/PAT を安全に保管（Keychain / 環境変数, リポジトリには置かない）
3. **予算・レート**
   - **API課金の上限（バジェット）必須**。24h稼働＝消費が続く。1タスクあたり/日あたりの上限を設ける。

---

## 4. 安全弁（自律の暴走を防ぐ）
- **レーン厳守**：無人マージは **dev/docs のみ**。本番・`.github/`・ゲーム核心は必ず人間承認（既存 `auto-merge-dev.yml` の guard が exit 1 で強制）。
- **1タスク＝1PR・最小変更**（CLAUDE.md）。
- **停止条件**（PROJECT_OPERATING_SYSTEM §14）：正典矛盾／仕様判断が要る／既存asset不明／本番影響／大規模リファクタ が必要なら**停止して報告**。
- **予算ガード**：上限到達で自動停止。
- **失敗時の自動リトライ上限**と、連続失敗時のアラート（Slack等）。

---

## 5. ネットワーク変更への耐性（接続先が変わっても止めない）
- ✅ **アウトバウンド中心なら、Wi-Fi/ルーター/IPが変わっても継続**（ネットに出られれば自動再接続）。GitHubセルフホストRunnerは外向きロングポーリングで再接続。
- ⚠️ **キャプティブポータル注意**：ブラウザ同意が要るWi-Fi（社内ゲスト/カフェ）は無人機が突破できず不通になる。**自宅の通常Wi-Fi/パスワードのみ**、または**有線LAN**を推奨。
- **ローカルIPは変わりうる**：外部から管理するなら **Tailscale（メッシュVPN）** で固定名到達、または新ルーターで **DHCP予約**。
- **公開IPが変わっても影響なし**（IPホワイトリストを使わない限り）。
- チェックリスト：①新Wi-Fi自動接続 or 有線 ②キャプティブポータルでない ③Tailscale/DHCP予約で管理経路確保 ④再起動後に launchd が自動復帰。

## 6. マルチエージェント分担（将来の並列化）
| エージェント | 役割 | トリガー |
|---|---|---|
| 調査 | 仕様/既存実装/ベンチの調査・要約 | 新Issue（調査ラベル） |
| 実装（Codex/Claude） | 実装→push→PR | Ready課題/実装Issue |
| 検証（Claude） | scene整合/実機/回帰 | PR作成/CI |
| レビュー（GPT） | 勝利条件でレビュー | PR |
- 現状は単一Claudeが兼務。Mac miniのディスパッチャで段階的に分離する。

---

## 7. セットアップ手順（概要・実機作業はMac mini上）
1. Homebrew / Git / GitHub CLI / Godot 4 / Node（必要なら）導入
2. セルフホストRunner登録（GitHub → Settings → Actions → Runners）＋ `launchd` 常駐化
3. Claude Code / Codex CLI 導入、APIキーをKeychainへ
4. ディスパッチャ・スクリプト（Ready課題ポーリング→headlessエージェント起動）を `launchd` 常駐化
5. スリープ無効・自動起動・（推奨）Tailscale
6. 予算上限・失敗アラート設定
7. まず **dev/docsの安全レーンだけ**を無人で通し、安定を確認してから範囲を広げる

---

## 8. 正直な限界
- 安全レーンは無人で回るが、**体験に関わる実装は確認レーンで人間承認が入る**（設計通り）。
- Mac miniはローカルマシン。**セットアップ（Runner導入・launchd・鍵配置）は実機作業**が必要（設計・手順・スクリプトは提供可能）。
- 完全無人の"クリエイティブ判断"は不可。方針・仕様・品質のGo判断は GPT/Miya が持つ。

---

## 9. 段階導入（推奨ロードマップ）
- **Step1**: セルフホストRunnerでGodotビルドを自動化（決定2のプロトタイプ検証に直結）
- **Step2**: dev/docsの安全レーンを無人で（Ready課題→実装→PR→CI→auto-merge）。前提（Allow auto-merge / GH_PAT）を整えてから
- **Step3**: 検証・レビュー・調査エージェントを分離して並列化
- **Step4**: 予算/アラート/停止条件を運用で締める
